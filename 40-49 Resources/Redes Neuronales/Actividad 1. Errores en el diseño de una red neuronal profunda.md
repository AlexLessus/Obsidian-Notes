Al diseñar y entrenar **redes neuronales profundas**, es muy común enfrentarse a errores estructurales, numéricos y metodológicos que impiden que el modelo converja o que generalice correctamente ante nuevos datos.

---

### Tabla de Errores Comunes en Redes Neuronales Profundas y Soluciones

| Categoría              | Error Común                                              | Causa o Síntoma Principal                                                                                                                                   | Cómo Solucionarlo                                                                                                                                                                                                   |
| :--------------------- | :------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Arquitectura**       | **Ausencia de no linealidad entre capas**                | Omitir funciones de activación entre capas densas; la red colapsa matemáticamente en un simple modelo lineal.                                               | Aplicar funciones de activación no lineales (como **ReLU**, **Leaky ReLU** o **GELU**) a la salida de cada capa oculta.                                                                                             |
| **Arquitectura**       | **Activación o pérdida inadecuada en la capa final**     | Usar una función de activación incompatible con la función de coste (ej. `softmax` con `binary_crossentropy`, o valores negativos con activación sigmoide). | Alinear la capa de salida y la pérdida: **Sigmoide + Binary Crossentropy** (clasificación binaria/multietiqueta), **Softmax + Categorical Crossentropy** (multiclase exclusiva) o **Lineal + MSE/MAE** (regresión). |
| **Arquitectura**       | **Sobreparametrización excesiva**                        | Diseñar una red con demasiadas capas o unidades para un conjunto de datos pequeño, provocando memorización rápida del ruido.                                | Reducir la capacidad del modelo (menos capas/unidades), aplicar el principio de la navaja de Occam o emplear arquitecturas preentrenadas (_Transfer Learning_).                                                     |
| **Dinámica Numérica**  | **Desvanecimiento del gradiente (_Vanishing Gradient_)** | Usar funciones saturantes (`sigmoid` o `tanh`) en capas profundas; los gradientes se vuelven casi cero al retropropagar y las primeras capas no aprenden.   | Usar activaciones de la familia **ReLU**, inicializaciones de pesos adecuadas (**He / Kaiming** o **Glorot / Xavier**), **Batch Normalization** o conexiones residuales (_skip connections_ tipo ResNet).           |
| **Dinámica Numérica**  | **Explosión del gradiente (_Exploding Gradient_)**       | Gradientes excesivamente grandes que provocan divergencia numérica o errores de tipo `NaN` / `Inf` en los pesos (común en RNNs).                            | Implementar **recorte de gradiente (_Gradient Clipping_)**, reducir la tasa de aprendizaje o utilizar arquitecturas con puertas como **LSTM / GRU**.                                                                |
| **Dinámica Numérica**  | **Mala escala de las entradas (Datos no normalizados)**  | Introducir características con rangos numéricos dispares (ej. edades de 0 a 100 junto a salarios de miles), deformando el paisaje de optimización.          | Estandarizar o normalizar las variables numéricas (media 0 y desviación estándar 1, o reescalar al intervalo \(\)) antes de introducirlas a la red.                                                                 |
| **Optimización**       | **Tasa de aprendizaje (_Learning Rate_) mal ajustada**   | Si es demasiado alta, la pérdida oscila o diverge; si es muy baja, el entrenamiento queda estancado en un progreso imperceptible.                           | Emplear optimizadores adaptativos (**Adam**, **RMSprop**) y usar programas de reducción progresiva (_Learning Rate Schedulers_) o búsqueda sistemática de _learning rate_.                                          |
| **Generalización**     | **Sobreajuste (_Overfitting_)**                          | La pérdida de entrenamiento sigue bajando mientras la pérdida de validación empieza a subir de forma constante.                                             | Aplicar **Dropout** en capas densas, regularización de pesos **\(L_2\) (_Weight Decay_)**, **Data Augmentation** para expandir la variedad de datos y **Early Stopping**.                                           |
| **Generalización**     | **Fuga de datos (_Data Leakage_)**                       | Ajustar los normalizadores (calcular media y desviación) utilizando todo el dataset antes de separar el conjunto de prueba o validación.                    | Dividir estrictamente en conjuntos de entrenamiento, validación y prueba antes de cualquier preprocesamiento; ajustar escaladores **únicamente con los datos de entrenamiento**.                                    |
| **Datos / Etiquetado** | **Desbalance severo de clases**                          | El modelo clasifica todo en la clase mayoritaria y obtiene alta precisión (_accuracy_) pero nula capacidad predictiva real.                                 | Utilizar métricas adecuadas (**F1-score**, **PR-AUC**), ajustar pesos de clases en la pérdida (`class_weight`), o aplicar remuestreo (_oversampling/undersampling_).                                                |

### Diagnóstico Rápido: La Regla del "Overfit a un Minilote"

Una buena práctica de depuración antes de entrenar la red en todo el conjunto de datos consiste en:

1. Tomar un lote diminuto (por ejemplo, entre 10 y 20 muestras).
2. Desactivar regularizaciones (_dropout_, _weight decay_).
3. Entrenar durante varias épocas.

- Si el modelo **no logra alcanzar un error cercano a cero** en esas pocas muestras, hay un error conceptual en el código (etiquetas transpuestas, formas de tensores incorrectas o gradientes desconectados).
- Si logra sobreajustar fácilmente ese minilote, la arquitectura básica funciona y los problemas posteriores corresponderán a regularización, volumen de datos o ajuste de hiperparámetros.
